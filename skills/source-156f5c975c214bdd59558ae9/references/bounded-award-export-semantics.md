# Bounded award exports

Declare row grain before retrieval: award, award transaction, cumulative award snapshot, or performance milestone. Keep different grains in separate tables. Specify exact filters, date field and inclusive boundaries, retrieval time, total available/loaded rows, deduplication key and truncation. Preserve original data and add enrichment with field-level source URL, retrieval time, entity match key and confidence; never overwrite an uncertain source field with an inferred value.

Award/action signed dates, period-of-performance start/end, modification dates and snapshot-as-of dates have different meanings. Label each. Transaction obligations are signed increments: a deobligation is negative. Cumulative snapshots are stock values at a point in time; never sum them with increments or count delivery milestones as additional obligations. Distinguish ceiling, potential value, current obligation, outlays and revenue. Unknown remains unknown.

Synthetic control: W1 T1 +100, T2 -20 yields net obligation 80. A W1 snapshot of cumulative 80 corroborates that result; adding it again to produce 160 fails. A milestone has no financial increment. Do not use a performance start date as the award signed date. Deduplicate transactions by stable transaction identity, not merely award ID (which would discard valid modifications).

For saved-search tracker universes, use `govtribe-capture-workflows` and its exhaustive export branch, resolved from that skill's own installed root, rather than ranking a sample. If that companion is unavailable, preserve the saved-search filters, retrieve every accessible result page with the appropriate approved search tool, reconcile loaded/available counts, and report any remaining retrieval as partial rather than substituting a ranked sample. Use source-inventory/table contracts to check requested columns, unique entities, exclusions and coverage. Report partial retrieval explicitly and keep a checkpoint for retry.

Before delivery, declare the requested row grain, source scope, columns, and expected coverage as the task contract. Report the delivery state as complete, partial, or blocked based on the executed coverage and financial-semantics checks, including the synthetic control above. Separate those checks and unresolved work from file-format or structural validity. If the host cannot create or inspect the requested spreadsheet or export, preserve the source-backed rows and provenance in a labeled Markdown table or CSV, deliver any validated source artifact, and state which requested artifact or rendering remains unavailable.
