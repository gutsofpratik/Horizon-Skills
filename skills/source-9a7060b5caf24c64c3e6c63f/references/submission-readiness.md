# Submission readiness

Use for a complete response package or an explicit readiness assessment. Reuse the requirement map and package checks owned by `govtribe-proposal-workflows`; do not turn every sentence edit into a full submission audit.

## Check the actual package

1. Confirm the controlling source versions and unresolved amendments/Q&A conflicts.
2. Match every required question, field, volume, form, attachment, and representation to its actual response location. Check consistency across files.
3. Check source-backed deadline, time zone, recipient/channel, naming, file type, size, volume separation, page/word/character limits, signatures, and amendment acknowledgments where applicable.
4. Check final exported files, not an earlier draft. Count pages from the actual render and apply the buyer's inclusion/exclusion rules for covers, tables, figures, and appendices.
5. Confirm that required answers are embedded where requested and that permitted links/attachments work as intended. Do not assume another volume or an old submission cures an omission.
6. Confirm that external files contain no accidental review notes, tracked edits, placeholders, private links, or unrequested qualifications. Preserve required disclosures and never hide a material uncertainty to appear complete.
7. Use the host's authoring and format tools for structural checks, rendering, and visual inspection. Check semantic headings, reading structure, table headers, alternative text, and other applicable accessibility requirements with available tooling. When working on a selected file, preserve its exact revision through `govtribe-document-editing`, resolving that bundled skill from its own installed root.

## Report coverage precisely

Record whether each applicable check passed, failed, remains unresolved, or is not applicable, with a source or observed result. A missing instruction, file, signature, or required check cannot be treated as a pass.

- A readable render does not prove full Section 508 conformance. State the actual scope of automated and manual checks.
- A timely draft does not prove timely government receipt. Use the actual authorized channel and observed confirmation before reporting submission.
- Do not promise a late-submission exception, infer a deadline when its interpretation is unresolved, or treat an upload acknowledgement as an award or acceptance determination.
- Keep any unresolved material requirement in review-draft status. Deliver the useful draft plus a concise internal list of exact blockers.
- If export, rendering, or visual inspection is unavailable, deliver any structurally validated source artifact and a labeled markdown or CSV fallback that the host can produce. Record the unperformed checks separately. Neither the fallback nor a word count proves a required final file, page limit, visual inspection, or accessibility result.

When all applicable authoring and final-format checks pass, describe the package as prepared for submission. Retain the distinction between preparation, authorized transmission, and observed receipt.
