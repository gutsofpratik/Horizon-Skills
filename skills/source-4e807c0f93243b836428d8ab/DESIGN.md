# 入戏.skill — 把一本书变成你能玩进去的一场戏

> 设计稿 v0.1 · 2026-08-29 · 待 sway 拍板

给它一本书（EPUB / TXT / PDF / 一个书名），产出一个**双击就能玩**的视觉小说：
你不是读者，你是书里的某个人，在原著真实发生过的那些抉择路口上，替他重新选一次。

---

## 一、这个东西凭什么不是又一个「让 AI 写个 galgame」

市面上已有的（调研 2026-08-29）：

| 已有 | 它做什么 | 缺口 |
|---|---|---|
| `worldwonderer/novel-to-game`（723★） | 小说 → 任意类型游戏原型，带原文溯源 | 不专攻视觉小说，官方示例是战棋/经营/3D；定位「15 分钟原型」；不谈版权 |
| `fracturedring/renpy-mcp` | 74 个工具的 Ren'Py 编辑器 MCP | 是「造 VN 的工具」，不是「书转 VN」 |
| `ZzzhangLK/ai-galgame` | 运行时实时生成剧情 | 玩一次烧一次 token，产物不可分发 |

中文侧没找到成品。**空位是这三条的组合**：只做视觉小说这一种形态做深 · 产物双击即玩 · 版权自觉。

下面五条是这个 skill 的全部主张。做不到任何一条，它就退化成同人文生成器。

### 1. 不覆盖全书，只取五到八场戏

一本三十万字的小说压成游戏，只有两条路：压成流水账，或者挑一场戏做深。视觉小说的时间单位是**一场戏**——两三个人、一个房间、一次对话、一个抉择——不是一章。

关键是不必把整本书喂给模型。先纯机械地算出「压强」，再让模型只读入选的那几场：

```
压强 = 对白占比 × 交锋次数 ÷ 在场人数
       （话密、来回多、人少 = 一场对峙）
```

**已实测**（`tools/scan_scenes.py`，Python 标准库，零安装）：《傲慢与偏见》124,116 词切成 67 场，压强前三是内瑟菲尔德客厅舌战（第八章）、凯瑟琳夫人上门摊牌、达西与伊丽莎白首次交锋——正是全书最锋利的三场对手戏。选戏这一步不烧 token 也能做对。

### 2. 你演谁，是开场必须问清楚的第一件事

三种，默认第二种：

| 演谁 | 好处 | 代价 |
|---|---|---|
| 原著主角 | 最直觉 | 玩家知道结局，选项没悬念；一改就「不是那个人了」 |
| **原著里被略过的边角人物**（默认） | 原著主线在背景里照常发生，你在缝隙里做选择；自由度高，不破坏原作 | 需要从书里找出这个人 |
| 全新外来者 | 最自由 | 和原著关系最弱，最容易滑成同人文 |

伊丽莎白身边那个只有三行字的女仆，在游戏里就是你。

### 3. 每一个分支点都要指得回原文的一句话

生成的剧本里，每个选择点都带一条出处注释，指向原书的章节和原句——「她本可以拒绝」。**找不到出处的分支，就是编的，砍掉。**

这是这个 skill 的立身之本。选择点长在原文上，玩游戏才是一种**重读**：你在追问「如果这里换一个答案会怎样」。竞品也做原文溯源，但溯到的是人物设定；这里溯的是**选择点本身**。

### 4. 不做好感度，做「理解度」

主流 galgame 的数值是好感度——选项在讨好角色。这里换成理解度：选项在问**你看懂她没有**。

- 选项不是「安慰她 / 嘲讽她」，是对她那句话的三种解读，只有一种贴着原著的人物逻辑
- 通关结算给一句判定：你读懂了这本书的哪些地方，哪些地方你一直在误读

玩完真的更懂这本书——这是「书改游戏」区别于「AI 写游戏」的唯一理由。

### 5. 结局里必须有一条是原著真实发生的事

标为**正典结局**。玩家撞上它的时候告诉他：这就是书里写的。其余路径是偏离。有了这个锚，其他分支才有参照，否则全是等价的胡编。

## 二、产物长什么样

**主产物：一个自包含 `index.html`。** 剧本以 JSON 内联，三百行左右 JS 负责打字机、立绘切换、分支、存档。零安装、零构建、能直接丢 GitHub Pages、能发给朋友。

调研确认 Ren'Py 的分发是硬伤：要么每平台打包几十上百 MB 的可执行文件，要么让用户自己装 SDK——AI 吐出脚本不等于用户能玩上。Ren'Py 工程和 WebGAL 工程做**可选的二级导出**。

**美术默认纯 CSS/SVG**：剪影、色块、渐变、排版做氛围，零下载、零版权、零外部依赖。可选升级两档：itch.io / OpenGameArt 的 CC0 素材库；AI 生图（人物一致性需求强时）。

**文风克隆原著，不是通用轻小说腔。** 先出一份文风档案（句长分布、比喻密度、对白与叙述比、标志性用词），生成时照着写。加缪该冷，狄更斯该絮叨。这条路子在 sunge-skill 上已经验证过。

## 三、版权：写进流程，不是写进免责声明

改编本身就是演绎作品，**即使一个字原文都不内嵌**，未经授权的改编 + 公开分发仍然侵权——人物、情节、结构都在保护范围内。

写死在 skill 里的四条：

1. 默认只在**本地**生成脚本和引擎，原文不写进产物、不进仓库
2. 开场问两个问题（作者卒年 / 首次发表年），给出「可公开发布 / 仅限本地自娱」两档结论，措辞明确标注非法律意见
   - 美国：1930 年及以前发表的已进入公有领域（2026 年起）
   - 中国及港澳台：作者终身 + 死后 50 年，算到当年年底
   - 陷阱：**译本有独立版权**，原著公版不代表某个中译本能用
3. 仓库里的完整可玩 demo 只用公有领域的书
4. 产物自动附 `CREDITS.md`：原著出处 + 素材许可 + 「本作品为改编，非原著」

## 四、适配范围（诚实划线，别吹「任何书」）

| 书的类型 | 能做到什么 |
|---|---|
| 小说 · 戏剧 | 最佳。戏剧尤其顺——本身就是剧本，对白可直接转 |
| 传记 · 历史非虚构 | 可以。做成「你是当时在场的某个人」 |
| 科普 · 工具书 | **不适合，直接说不适合**，别硬做 |

## 五、v1 交付清单

```
ruxi-skill/
├── SKILL.md              # 五阶段工作流：拆书 → 选戏 → 定角 → 写本 → 打包
├── prompts/              # 按阶段拆分的提示词
├── tools/
│   ├── scan_scenes.py    # ✅ 已实测：零依赖 EPUB/TXT → 场景压强表
│   ├── build_html.py     # 剧本 JSON → 单文件 index.html
│   └── export_renpy.py   # 可选二级导出
├── references/
│   ├── adaptation.md     # 小说改视觉小说的方法论（三、四、五条主张的展开）
│   ├── style-clone.md    # 文风档案怎么做
│   └── script-schema.md  # 剧本 JSON 的结构定义（决定生成是否稳定）
├── demos/
│   ├── metamorphosis/    # 《变形记》— 4 个角色一个房间，证明能做严肃文学
│   └── pride/            # 《傲慢与偏见》— 攻略与好感度，证明能做主流玩法
├── README.md / README_en.md / ROADMAP.md / LICENSE
```

两个 demo 的分工：《变形记》（卡夫卡 1915，密闭、心理压迫，几乎是现成的视觉小说）证明它能处理严肃文学；《傲慢与偏见》证明它能做玩家预期里的那种 galgame。

备选 demo：《化身博士》（双重人格 = 天然双线）、《竹林中》（多视角互相矛盾，天生多结局）、《玩偶之家》（本身是剧本）。中文侧《聊斋志异》单篇最合适——每篇短、一人一妖、结构闭合，一本书能批量出十几个小 demo。

## 六、还没想清楚的

1. **《变形记》里玩家演谁？** 格里高尔已经变成虫，妹妹葛蕾特是最好的选择——但那就是主角路线，回到主张 2 的第一种。可能需要承认：密闭剧的边角人物不够用。
2. **一场戏要写多少字才够玩。** 五到八场 × 每场多少？先做一个 demo 量出来，再定生成配额。
3. **理解度的判定谁来做。** 生成时把「正解」写死进剧本（省事、可离线），还是留一个 LLM 接口实时判（更准、但产物不再自包含）。倾向前者。
