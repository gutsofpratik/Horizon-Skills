# Distribution and access

Read this reference when implementation changes cross-product compatibility, unlicensed access, licensing, sharing, Marketplace behavior, or installation eligibility. Route a broad readiness assessment to `forge-app-review`.

Establish the intended audience and distribution model only when it affects architecture or code. Retrieve current rules before changing manifest licensing, module access, product compatibility, or egress that affects eligibility.

Treat changes to scopes, egress, licensing, supported Atlassian apps, and unlicensed access as installation or version decisions as well as code changes. Explain required consent, upgrade, and testing effects without enabling sharing, submitting a listing, or changing production distribution unless explicitly requested and authorized.
