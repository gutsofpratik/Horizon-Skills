# Real-World Proposal Routing Examples

Use these patterns to recover proposal intent from the active record, attached files, and prior turns.

## Route here

### RFI or sources-sought response package

Example: "Create an RFI response for our company based on the attached."

- Recover and prioritize the attached RFI, PWS/SOW, survey, information sheet, amendments, and instructions.
- Draft the requested response package, which may include a cover letter, narrative, survey answers, capability information, checklist, and submission email.
- Ground company claims in provided or retrieved evidence and flag facts that require confirmation.
- Use [Draft Response and Fill Template](draft-response-and-fill-template.md).

### Compliance and submission checklist

Example: "Build a compliance and submission checklist covering registrations, pricing documents, financial responsibility evidence, regulatory requirements, thresholds, and electronic submission steps."

- Synthesize solicitation instructions, program rules, attachments, amendments, and source-package files.
- Preserve exact wording and citations where a missed requirement could make the submission noncompliant.
- Produce an operational checklist with owner, status, source, deadline, and risk where requested.

### Iterative project-plan or template workflow

Examples:

- "Draft a project plan for this effort."
- "Provide it as a Word document."
- "Use this template to create the draft."
- "Fill this out too."

Treat these as one continuing proposal workflow. Reuse the same target, source inventory, requirements, accepted language, and formatting decisions. Populate the provided template rather than starting over in a different structure.

### Ambiguous response-strategy prompt

Example: "How do I respond to this?"

When the active opportunity, RFI, or file set resolves cleanly, return a concise response strategy with buyer intent, required response components, evidence needed, risks, and recommended structure. Do not ask the user to restate "this" unless multiple targets remain.

## Context to reuse

- active opportunity, pursuit, solicitation, RFI/RFQ, amendment set, and source files
- user's company, approved capabilities, differentiators, vehicles, certifications, and past performance
- prior draft documents, templates, and user edits
- requested output format, submission method, and deadline
- proposal stage and whether the user needs advice, a draft, or a finished artifact

Do not invent company proof or commitments. Keep user-confirmation placeholders visible.

## Normal handoffs

- Capture to Proposal after a pursuit passes qualification or the user requests a formal response artifact
- Pricing to Proposal for a submission email, price narrative, pricing workbook, or price-volume support
- Proposal to Pricing when staffing, FTE, wrap, wage, rate, or PTW evidence needs analysis
- Proposal to Capture when the user is still asking whether to bid or how to position the pursuit

## Do not route here

- "Find the FTE number in this document." Use file extraction unless analysis or a proposal artifact is requested.
- "What building does this project take place in?" Use source-file fact retrieval.
- Broad market scans or buyer-pattern analysis
- Exact incumbent tracing or competitor ranking before proposal development
- Simple award-status or vehicle-lookup questions
