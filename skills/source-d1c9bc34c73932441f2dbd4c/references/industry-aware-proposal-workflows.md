# Industry-Aware Proposal Workflows

Use this reference alongside the matching proposal workflow when the solicitation, RFI/RFQ, source package, response template, workbook, compliance matrix, annotated outline, or buyer context clearly points to an industry. Industry context identifies where to inspect; only source evidence creates requirements.

## Progressive-disclosure rule

1. Load the task-specific proposal workflow first.
2. Select one primary procurement lane below.
3. Load a mission-domain modifier only when it materially changes the response.
4. Do not load every industry reference.

For mixed procurements, choose the lane that controls the response architecture or highest-risk compliance obligations. Add one secondary lane only when it materially changes requirements, evidence, outline structure, pricing dependencies, or artifact QA.

## Select the primary procurement lane

- [Products, Supply, and Equipment](industry-proposal-products-supply-equipment.md): item eligibility, source control, delivery, QA, packaging, inspection, warranty, documentation, and supply/equipment response architecture.
- [Digital, IT, Cyber, and Data](industry-proposal-digital-it-cyber.md): system boundaries, authorization, cyber/cloud/software/data requirements, privacy, accessibility, support, transition, evidence, and digital response architecture.
- [Professional and Mission-Support Services](industry-proposal-professional-services.md): labor mix, key personnel, compensation, transition, management, quality, staffing continuity, workshare, and service response architecture.
- [Construction, AEC, and Facilities](industry-proposal-construction-aec-facilities.md): site, wage, bonding, safety, schedule, submittal, QA/QC, trades, design-build, A-E, facilities, and sealed-bid controls.
- [Mission-Domain Modifiers](industry-proposal-mission-domain-modifiers.md): healthcare/life sciences; R&D/scientific; environmental/energy; transportation/aviation/maritime; public safety/emergency response.

A mission modifier supplements the primary procurement lane. It never replaces it.

## Evidence destinations

Keep each item in the correct destination:

- source-confirmed requirement -> compliance matrix, checklist, or mandatory outline content
- buyer evaluation signal -> evaluation crosswalk, response strategy, or annotated outline
- company evidence -> proof point, past performance, resume, credential, or artifact input
- industry practice not confirmed by source -> question, risk, assumption, or check to verify
- proposal strategy -> drafting guidance, win-theme placeholder, graphic concept, or reviewer note

Never promote a common industry practice into a compliance requirement without source support.

## Source hierarchy and amendment discipline

- Prefer the latest conformed solicitation, amendments, Q&A, buyer templates, and incorporated attachments.
- Preserve exact source citations and controlling-language distinctions.
- When sources conflict, identify the control question rather than silently choosing.
- Keep source-confirmed requirements separate from likely checks, recommendations, and company claims.

## Base-workflow preservation

- Preserve the base solicitation-intelligence, compliance, workbook, annotated-outline, response-drafting, template-filling, validator, and render-QA procedures.
- Use industry context to sharpen source inventories, extraction targets, questions/risks, outline architecture, evidence needs, workbook rows, and handoffs.
- Do not invent capabilities, credentials, certifications, staffing, pricing, technical status, licenses, or commitments.
- Hand pricing analysis to `govtribe-pricing-data` and pursuit qualification to `govtribe-capture-workflows`.

## Current-rule verification

The controlling solicitation, amendment set, incorporated clauses, current official sources, and jurisdiction-specific law govern. Verify current versions at execution time.
