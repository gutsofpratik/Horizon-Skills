第一个劝你删 skill 的 skill.

整个生态都在做加法 —— awesome 列表收录上千个 skill，单个仓库敢塞三百多个。没有人做减法。 但 skill 不是免费的：每装一个，每一轮都在付它的 token 税；模型每变强一代，就有一批 skill 从资产变成负债。

断舍离.skill 删的是「教模型做它已经会的事」，
留的是「告诉模型它不可能知道的事」。

为什么要减

skill 不是免费的，你在付三重成本

装的时候都有理由，删的契机永远不来 —— 于是 skill 目录只增不减，而模型一直在变强。

token 税

它的名字和描述进每一轮的系统提示词，是常驻支出。十几个 skill 起步就是每轮两千 token，你为它付钱，无论今天用不用得上。

误触发

描述之间互相抢活。触发错一次比没有 skill 更糟 —— 模型带着一份过时的操作手册，理直气壮地走错方向。

腐烂

里面写死的路径、API、模型名会过期。一个腐烂的 skill 每触发一次就误导一次，而它自己不会告诉你它已经过期了。

效果

不是「删几个看着不顺眼的」

是对着你此刻的模型、harness、MCP，逐个过堂、拿证据判。

怎么判

三分法定性，五问取证，盲测复核

「模型越强 skill 越没用」只对第一类成立 —— 分不清类型的清理，删的都是不该删的那些。

类型定义命运
能力型教模型怎么想、怎么做的通用方法模型升级会淘汰它 —— 审计重点
环境型包装工具、补 harness 缺的功能harness 与 MCP 演进会取代它
知识型私有事实：账号、路径、内部约定永不因模型变强而过时（红线保护）
问一模型已内化？
问二harness 已自带？
问三MCP 已接管？
问四被吞并 / 重复？
问五已经腐烂？

判决不止删留两档

能力型 skill 被判移除之前，先开一个不加载它的子 agent 裸做它最典型的任务 —— 裸做不逊色才准删。证据，不是直觉。

判决含义
✂️ 移除证据确凿 → 归档（可恢复），永不 rm
🔧 修剪混合型：删过时的说教，留值钱的事实，常见 200 行剪成 10 行
🔗 合并触发词打架的重复者，并入较优者
⏳ 缓刑证据不足不硬判，记为下次审计重点
✅ 保留它挣回了自己的 token 税

凭什么放心

一个要动你 skill 目录的工具，安全设计就是它的全部信用

  • ✓永不 rm —— 一切移除都是挪进归档目录：--restore 一条命令恢复，MANIFEST 全程留痕。
  • ✓不确认不动手 —— 判决表先给你过目，逐条可否决。
  • ✓红线保护知识型 —— 私有事实、团队政策、被引用的脚本，证据再硬也不删。
  • ✓归档前搜身 —— 过时 skill 正文里常埋着不过时的私有事实（URL、账号、脚本），先迁出再归档。
  • ✓判决必须挂证据 —— 盲测记录、指名道姓的替代者（哪个内建工具、哪个 MCP）、腐烂实证，嘴判无效。
  • ✓自我审判条款 —— 断舍离自己每轮也收你约 180 token 的描述税，得靠省下更多来挣回；若你的模型裸做审计已同样好，请把断舍离也断舍离。
